# P1.2.4.1 — Canonical RecognitionEvent MQTT bridge

## Status
IMPLEMENTED — runtime broker verification pending.

## Goal
Publish an already-confirmed `RecognitionEvent` through the existing `src/devices/mqtt_adapter.py` transport without creating a second biometric decision path or sending embeddings/images.

## Implementation
- `app/mqtt_bridge.py` owns only the mapping from the canonical Pydantic event to the MQTT envelope.
- Existing MQTT topic/QoS implementation remains authoritative.
- Event uses the device-scoped `face/v1/devices/{device_id}/event` topic.
- QoS 1, non-retained.
- No embedding or image data is serialized.

## Verification
Unit test must prove:
1. canonical event fields survive serialization;
2. `person_id`, model/embedding versions, quality, liveness, similarity, margin, frame confirmation and timestamp are present;
3. no embedding field is emitted;
4. QoS is 1 and retain is false;
5. the existing MQTT adapter is used rather than a parallel client/topic implementation.

Runtime gate remains open until a real broker test verifies publish/subscribe and duplicate delivery behavior with the PostgreSQL idempotency boundary.

## Completion criteria
- bridge implementation merged;
- unit test passes;
- real broker integration passes;
- duplicate event delivery causes no duplicate downstream action;
- no biometric decision logic exists in MQTT transport.
