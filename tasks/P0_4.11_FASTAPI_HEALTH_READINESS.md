# P0.4.11 — FastAPI health/readiness boundary

## Status
IMPLEMENTED — execution receipt pending

## Objective
Create the first stable HTTP service boundary without coupling transport to recognition semantics.

## Endpoints
- `GET /healthz`: process is alive.
- `GET /readyz`: recognition engine readiness state.

## Verification
Use FastAPI `TestClient` to verify both endpoints and the false/true readiness states.

## Acceptance
- health is independent of model readiness;
- readiness is false until the engine is actually initialized;
- no recognition/person_id endpoint is exposed before model, FAS, and vector dependencies have an explicit readiness contract;
- tests have an execution receipt before PASS.
