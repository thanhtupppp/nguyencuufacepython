# P0.4.15 — Leakage-safe pgvector benchmark

## Goal
Prevent self-query leakage in the P0.4.14 retrieval benchmark. A query embedding must never be allowed to retrieve itself from the gallery.

## Motivation
The existing P0.4.14 harness selects an enrollment embedding per person and queries the same gallery. That can make recall look artificially perfect because the query template is its own nearest neighbor. This is not a valid recognition/retrieval benchmark.

## Implementation
`benchmarks/pgvector_leave_one_out_benchmark.py`

Each query is an actual stored embedding, but its own `face_embeddings.id` is excluded from both exact and HNSW galleries. Only people with at least `MIN_TEMPLATES_PER_PERSON` templates are eligible, so the query person retains independent gallery evidence.

## Metrics
- exact-vs-HNSW Top-K agreement;
- query-person Recall@K;
- HNSW p50/p95/p99/mean latency;
- gallery size and template count;
- pgvector version;
- HNSW `ef_search` and candidate pool.

## Verification
Unit tests assert that both exact and HNSW SQL exclude the query embedding and group results by `person_id`.

Real execution requires the project PostgreSQL/pgvector environment and real ArcFace embeddings. No synthetic accuracy claim is permitted.

## Completion criteria
- self-query leakage test passes;
- benchmark runs against real PostgreSQL/pgvector;
- results are recorded for the defined matrix;
- no recognition threshold is changed to compensate for retrieval behavior.
