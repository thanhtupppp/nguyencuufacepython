# P0.4.9 — HTTP + WebSocket action adapters

## Goal
Deliver the same already-authorized `ActionEnvelope` over HTTP and WebSocket without changing identity or authorization semantics.

## Implementation
- `src/events/http_adapter.py`
- `src/events/websocket_adapter.py`
- shared `validate_action_envelope()` remains the authorization boundary.
- HTTP sends `Idempotency-Key: event_id`.
- WebSocket carries the same canonical JSON fields and `event_id`.

## Verification
Run unit tests and then integration/HIL tests against real endpoints. Verify that `event_id`, `person_id`, `track_id`, `camera_id`, and authorization state are preserved byte-for-byte at the envelope field level.

## Acceptance
- only `AUTHORIZED` envelopes are accepted;
- HTTP uses the same `event_id` as idempotency key;
- WebSocket preserves the same event identity;
- no adapter computes recognition scores or creates `person_id`;
- duplicate delivery remains safe at the consumer using durable event-id deduplication;
- execution receipt is recorded before marking this task PASS.
