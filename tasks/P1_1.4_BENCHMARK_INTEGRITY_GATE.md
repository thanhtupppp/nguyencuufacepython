# P1.1.4 — Vector benchmark integrity gate

## Status
IMPLEMENTED — benchmark audit requirements added. Real PostgreSQL execution remains pending.

## Goal
Prevent the vector benchmark from producing misleading retrieval conclusions before the real database run.

## Findings from audit
- `tools/benchmark_pgvector_retrieval.py` supports production/candidate/candidate_rerank/prototype/prototype_rerank modes.
- The benchmark uses synthetic vectors only; this is appropriate for DB/retrieval mechanics but cannot establish biometric recognition accuracy.
- The current benchmark must distinguish retrieval recall from recognition accuracy and must keep an exact person-level oracle independent of ANN settings.
- `--repeats` exists in the newer ANN harness but is not currently used to repeat timed queries; timing results therefore need a fix before being used for p95/p99 decisions.
- Candidate-first retrieval must deduplicate by person_id before final top-K; raw template hits cannot be counted as person-level results.
- Prototype and template-level paths must use identical active/model-version filtering and the same query set.

## Verification contract
For every scenario report:
- exact person-level oracle recall@1/@5/@10;
- ANN recall against that oracle;
- missing person rate;
- duplicate person_id rate;
- p50/p95/p99 latency after warm-up;
- cold/warm distinction;
- PostgreSQL and pgvector versions;
- HNSW `ef_search` and iterative_scan;
- candidate oversampling factor;
- active ratio and model-version selectivity.

Timing protocol: discard warm-up queries, then execute repeated identical scenario queries with deterministic query seeds. Report median and tail latency separately from recall. Never alter recognition thresholds to compensate for retrieval loss.

## Architecture decision rule
1. If template-level retrieval has required recall, keep it as correctness baseline.
2. Candidate-first is accepted only if person-level recall is equal to baseline within the project safety budget and latency improves materially.
3. One-vector-per-person is accepted only if prototype recall passes the same gate; otherwise keep multi-template enrollment.
4. Any retrieval loss that can change the top-1 identity is a blocker regardless of latency improvement.
