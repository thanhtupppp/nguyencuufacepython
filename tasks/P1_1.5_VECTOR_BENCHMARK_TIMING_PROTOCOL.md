# P1.1.5 — Vector benchmark timing protocol

## Status
IMPLEMENTED — execution pending real PostgreSQL/pgvector.

## Goal
Make vector retrieval latency measurements reproducible enough for an architecture decision without mixing cold-start, query generation, or one-off timing noise into the result.

## Scope
`tools/benchmark_pgvector_retrieval.py`

The benchmark must:
- generate the deterministic query set once per run;
- execute configurable warm-up passes that are excluded from reported timing;
- execute the exact same query set for every measured repetition;
- report the number of timed samples;
- report p50, p95, and p99 latency;
- keep retrieval correctness/recall independent from recognition threshold tuning;
- identify that reported latency is database retrieval + the benchmark's measured execution path, not model inference latency.

## CLI contract
- `--queries >= 1`
- `--repeats >= 1`
- `--warmup >= 0`

Default protocol: 50 queries, 5 measured repetitions, 1 warm-up pass.

## Correctness rules
1. Exact person-level oracle is generated independently of ANN retrieval.
2. Recall is computed by `person_id`, never template row ID.
3. Active-person and model-version filtering remain enabled for the production/candidate paths.
4. Prototype and candidate modes are not allowed to redefine the oracle.
5. Recognition thresholds/margins must not be changed to compensate for retrieval misses.

## Timing rules
1. Build/load/index setup is outside the measured query timer.
2. Warm-up executions are excluded from percentile statistics.
3. Every measured repetition uses the same deterministic query set.
4. p50/p95/p99 are calculated from all timed samples.
5. A run must report `timed_samples = queries * repeats`.

## Completion criteria
- `--repeats` changes the number of measured samples.
- `--warmup` runs before measurements and does not change `timed_samples`.
- p50/p95/p99 are present in output.
- repeated runs use identical query vectors for the same seed.
- no production database/table is required; the benchmark uses its dedicated benchmark data path.
- real PostgreSQL/pgvector execution receipt is still required before P1.1.5 is marked PASS.
