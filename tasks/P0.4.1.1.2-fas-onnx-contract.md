# P0.4.1.1.2 — FAS ONNX graph and preprocessing contract

Status: IMPLEMENTED / EXECUTION BLOCKED ON ARTIFACT BYTES

## Objective

Verify the anti-spoof candidate's actual ONNX graph contract before any quality benchmark. The project must not infer dtype, tensor layout, output semantics, or score direction from README claims alone.

## Verified upstream evidence

For `facenox/face-antispoof-onnx` at commit `fa6489fb221dcf6b803095ab4b15a0fa0f56cfe5`:

- upstream inference expects a 2-class output;
- class 0 is treated as Real and class 1 as Spoof;
- decision score is `real_logit - spoof_logit`;
- preprocessing resizes with letterboxing, uses Lanczos when upscaling and area interpolation when downscaling, pads with `BORDER_REFLECT_101`, converts HWC to CHW, and scales float32 values by 255;
- the upstream preprocessing code performs no explicit BGR↔RGB conversion, so the caller's channel order must be verified against the capture/crop path before production benchmarking.

## Local verification

Run:

python tools/inspect_fas_onnx.py path/to/best_model_quantized.onnx

The resulting receipt must be archived with the benchmark run. It must report the actual input/output tensor shapes and types from ONNX Runtime.

## Acceptance criteria

1. Exact artifact bytes are available locally.
2. SHA-256 is computed and pinned in `configs/fas_artifacts.yaml`.
3. ONNX Runtime inspection succeeds.
4. Actual input tensor shape/type agree with the preprocessing adapter.
5. Actual output shape is `[N, 2]` or the manifest is updated with an explicit adapter.
6. Real/Spoof semantics and score direction are supported by upstream source and not inferred from tensor order alone.
7. Channel order is explicitly fixed in the project preprocessing contract.
8. Weight license is independently verified before redistribution or packaging.

## Current blockers

- Model binary is not available in this repository, so SHA-256 cannot be truthfully pinned from source inspection alone.
- The upstream README states 128×128 RGB, while its preprocessing implementation performs no channel conversion. This must be resolved using the actual capture/caller path, not guessed.
