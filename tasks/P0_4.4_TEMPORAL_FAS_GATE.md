# P0.4.4 — Temporal FAS gate implementation

## Objective
Prevent a single noisy passive anti-spoof frame from authorizing face recognition. Produce a deterministic, fail-closed temporal LIVE gate while keeping model threshold calibration separate from runtime state logic.

## Implementation
- `src/fas/temporal_gate.py`
- `TemporalFasGate` defaults to 3 consecutive verified LIVE observations.
- Any unverified/error observation breaks the LIVE streak.
- A verified SPOOF observation blocks the track immediately by default.
- A track change invalidates prior FAS evidence.
- Frame indices must increase monotonically.

## Verification
Use deterministic replay sequences covering:
1. LIVE, LIVE, LIVE -> `LIVE_CONFIRMED`.
2. LIVE, ERROR, LIVE, LIVE -> never confirms before three new LIVE frames.
3. SPOOF -> `SPOOF` immediately.
4. track A LIVE, then track B LIVE -> evidence does not transfer.
5. duplicate/out-of-order frame -> hard failure.
6. confirmed LIVE followed by ERROR -> no new authorization evidence is added.

## Acceptance
- deterministic state transitions;
- no FAS evidence crosses `track_id`;
- no unverified frame contributes to LIVE confirmation;
- no threshold is hard-coded as a model-quality claim;
- runtime gate remains fail-closed.

## Important limitation
This is a runtime safety mechanism, not evidence that MiniFASNet or any other FAS model has acceptable APCER/BPCER/ACER. Thresholds and model selection remain blocked on P0.4.2 artifact verification and P0.4.1 locked evaluation.
