# P0.4.3 — Anti-spoof fail-closed runtime contract

## Objective
Define the runtime boundary so an unresolved/unverified anti-spoof artifact can never produce a trusted LIVE decision or reach identity confirmation.

## Runtime contract
`FAS_UNVERIFIED`, `FAS_ERROR`, `FAS_SPOOF`, and `FAS_LOW_CONFIDENCE` are non-authorizing states.

Only `FAS_LIVE_CONFIRMED` may allow the pipeline to continue to ArcFace identity retrieval.

Required ordering:

SCRFD → face crop → FAS → alignment → ArcFace → vector retrieval → temporal confirmation.

## Required invariants
- FAS model provenance must be verified before runtime activation.
- Missing model bytes, SHA mismatch, unresolved weight license, invalid ONNX contract, inference error, or preprocessing contract mismatch must fail closed.
- FAS must be associated with the same `track_id`/face crop used for recognition; no cross-track reuse of a LIVE result.
- A spoof/rejected FAS result must not increment temporal identity evidence.
- FAS state is separate from `person_id`; anti-spoofing never assigns identity.
- Runtime logs must expose reason codes without storing raw biometric frames by default.

## Verification
Add deterministic unit tests for every fail-closed path and an integration sequence proving:
1. spoof → no ArcFace authorization;
2. FAS error → no ArcFace authorization;
3. unverified artifact → service refuses activation;
4. live + accepted quality → identity retrieval may proceed;
5. track change → previous FAS decision cannot authorize the new track.

## Acceptance
- explicit state enum and reason codes;
- tests cover all fail-closed paths;
- no path allows `CONFIRMED person_id` from a non-live state;
- documentation matches actual runtime ordering.
