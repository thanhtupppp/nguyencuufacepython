# P0.2 — Real-image quality gate calibration

Status: READY-NEXT (blocked only on the selected recognition model + authorized image manifest).

## Objective
Build a recognition-specific quality gate that rejects samples likely to cause false matches or unstable embeddings before vector retrieval. The gate must be calibrated from real images and must not invent a universal quality threshold.

## Pipeline contract
1. SCRFD detects face and returns 5 landmarks.
2. Apply the repository's 5-point similarity alignment to 112x112.
3. Compute the selected recognition embedding.
4. Compute deterministic image/face quality features: face pixel size, bbox confidence, landmark geometry/alignment error, estimated yaw/pitch/roll when available, blur/sharpness, exposure/saturation, occlusion proxies, and embedding quality signal if the selected model exposes one.
5. Produce a quality decision: ACCEPT / REJECT / REVIEW, with machine-readable reason codes.

## Research candidates
- Baseline deterministic quality features: required first.
- SER-FIQ: evaluate only if a compatible implementation/model is available; it estimates quality from embedding robustness and does not require quality labels. https://arxiv.org/abs/2003.09373
- MagFace quality magnitude: evaluate only if the selected recognition model is MagFace-compatible; do not apply MagFace magnitude to a plain ArcFace embedding and call it equivalent. https://arxiv.org/abs/2103.06627

## Calibration protocol
- Split by person_id: train/calibration, validation, locked test.
- Never tune thresholds on the locked test set.
- Compare genuine-pair and impostor-pair distributions with and without the quality gate.
- Report FMR/FNMR and TAR at fixed low-FAR operating points where sample count permits, plus rejection rate and quality-gate false reject rate.
- Evaluate quality strata independently: frontal, moderate pose, profile, blur, low light, occlusion, small face, glasses/mask where authorized.

## Acceptance criteria
- Quality gate lowers false-match risk at the selected operating point without an unacceptable genuine rejection increase.
- Thresholds are stable across camera/device slices used by the project.
- Every rejection has a reason code and reproducible score.
- Calibration artifact records model version, preprocessing, dataset manifest, thresholds, and SHA256s.
- Locked-test results are generated exactly once per candidate release.

## Deliverables
- versioned quality-gate config;
- calibration/evaluation JSON;
- reason-code schema;
- reproducible benchmark script;
- decision note explaining whether the gate is enabled by default.
