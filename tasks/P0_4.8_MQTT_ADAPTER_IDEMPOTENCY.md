# P0.4.8 — MQTT adapter, delivery semantics, and idempotency receipt

## Status
IMPLEMENTED — design/task contract; runtime adapter and execution receipt remain next implementation target.

## Objective
Bind the transport-neutral `ActionEnvelope` to MQTT without allowing MQTT to change recognition semantics, and make duplicate delivery safe for physical actuators.

## Scope
- Fixed topic namespace: `face/{device_id}/actions/v1`.
- Publish only `AUTHORIZED` `ActionEnvelope` payloads.
- Preserve `event_id` byte-for-byte as the idempotency key.
- Default QoS target: QoS 1; retained messages MUST be disabled for physical actions.
- Consumer must persist/check `event_id` before executing an action.
- Duplicate `event_id` delivery must produce an acknowledgement/dedup receipt, not a second physical action.
- Reconnect/retry must not create a new event ID.
- MQTT credentials/TLS remain transport configuration, never part of recognition logic.

## Verification
1. Publish one authorized envelope and capture the exact payload/event_id.
2. Simulate broker reconnect and publish retry; assert identical event_id.
3. Deliver the same message N times to the consumer; assert exactly one physical-action execution.
4. Deliver two different event IDs; assert two independent actions.
5. Verify QoS 1 and `retain=false` at the adapter boundary.
6. Reject non-AUTHORIZED envelopes before publish.
7. Record an execution receipt containing event_id, device_id, action outcome, and dedup status.

## Safety invariants
- No ArcFace score, vector distance, FAS score, threshold, or `person_id` generation exists in MQTT code.
- MQTT failure never upgrades an authorization state.
- Duplicate delivery is safe by consumer-side idempotency, not by assuming the broker delivers exactly once.
- A retained physical-action message is forbidden.

## Completion criteria
- MQTT adapter implements the shared transport contract.
- Focused adapter tests pass.
- Duplicate-delivery test demonstrates one physical action for N identical deliveries.
- Execution receipt is emitted for first execution and duplicate deliveries.
- TLS/QoS/topic/retain configuration is explicit and tested.
