# P0.2.1 — Deterministic quality-feature contract

Status: IMPLEMENTED-CONTRACT; empirical calibration remains blocked on an authorized image manifest and selected recognition artifact.

## Objective
Make quality-gate outputs deterministic, versioned, and machine-readable before threshold calibration. Do not treat the current thresholds as production-calibrated.

## Required features
- face width/height and normalized face area;
- detector confidence;
- Laplacian variance on the detected face crop;
- mean brightness and exposure bounds;
- 5-point landmark geometry and alignment residual;
- pose proxy (yaw/pitch/roll) only as a deterministic feature, not a calibrated pose estimator;
- occlusion/mask reason codes when enabled.

## Decision contract
The gate must return one of `ACCEPT`, `REJECT`, `REVIEW` and stable reason codes. Multiple rejection reasons are preserved in deterministic order. A quality score is diagnostic until calibrated on the locked validation protocol.

## Verification
- identical input + configuration => identical JSON-compatible result;
- malformed landmarks/bbox fail closed;
- every reject path has a stable reason code;
- configuration records `quality_gate_version` and all thresholds;
- no threshold is declared production-ready without person-disjoint validation and locked-test evidence.
