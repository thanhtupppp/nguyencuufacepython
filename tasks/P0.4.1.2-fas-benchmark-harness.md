# P0.4.1.2 — Common FAS benchmark harness

## Goal
Evaluate anti-spoof candidates under one preprocessing, split, metric, and latency protocol. Never select a production model from upstream headline accuracy.

## Inputs
- `configs/fas_artifacts.yaml` for pinned model metadata.
- Local authorized evaluation data only.
- Face crops generated by the same project alignment/crop protocol.

## Required metrics
- APCER
- BPCER
- ACER
- ROC-AUC
- EER
- threshold at the selected security operating point
- false-accept counts by attack type
- p50/p95 inference latency
- model size

## Required execution matrix
- x86 CPU
- ARM64 CPU (Raspberry Pi class)
- Android/ARM64 when a reproducible runtime is available

## Implementation
- `tools/evaluate_fas.py` provides a fail-closed ONNX evaluator and emits machine-readable JSON.
- The runner verifies the manifest SHA-256 before loading an artifact.
- Dataset contract is explicit: `<dataset>/real/**` and `<dataset>/attack/**`.
- The current image preparation function is intentionally temporary; it must be replaced by the project-locked SCRFD/alignment crop before production benchmark results are accepted.

## Acceptance criteria
- Manifest verification passes before evaluation.
- All candidates receive identical crop/alignment and evaluation splits.
- Results are emitted as machine-readable JSON plus a human-readable receipt.
- No production promotion unless the candidate satisfies the project's false-accept gate and latency budget.
- Cross-dataset/device results are reported separately from in-domain results.
- No result is considered valid while the manifest contains placeholder hashes or the project alignment adapter is not used.
