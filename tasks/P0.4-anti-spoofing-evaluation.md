# P0.4 — Anti-spoofing / presentation-attack evaluation

Status: READY-NEXT after tracking and recognition calibration.

## Objective
Prevent a face embedding match from being accepted when the input is a presentation attack: printed photo, screen replay, or replayed video. Liveness is a separate security gate from face similarity and image quality.

## Candidates
1. Baseline passive RGB MiniFASNet-family ONNX model with a reproducible, license-compatible artifact.
2. InsightFace 2.0 optional RGB liveness as a challenger; its model must pass the same artifact/license gate. The current InsightFace package documents liveness as an explicit optional gate before recognition.
3. Active challenge-response is a future escalation only if passive RGB performance is insufficient.

## Verification
Build an attack matrix:
- bona fide live faces;
- printed photo;
- phone/tablet screen replay;
- video replay;
- different screen brightness/refresh conditions;
- masks/occlusion where relevant;
- lighting and camera-distance slices.

Report APCER, BPCER, ACER, attack-specific error rates, threshold stability, and latency. Never use a vendor headline accuracy as the acceptance criterion.

## Architecture contract
`liveness_pass` gates the creation of a trusted recognition event. A liveness failure must not be converted into `unknown person_id` or a similarity score that can trigger an action.

Suggested event state:
`DETECTED -> QUALITY_OK -> LIVENESS_OK -> RECOGNITION_CONFIRMED -> ACTION_ALLOWED`

Any failed gate terminates the trusted action path and records a reason code.

## Completion criteria
- artifact + SHA256 + license recorded;
- attack matrix and authorized test manifest pinned;
- APCER/BPCER/ACER reported;
- low-FAR face recognition evaluated separately from liveness;
- CPU/edge latency measured;
- false accept action path is blocked on liveness failure;
- deterministic regression fixture exists.

## Next task
Integrate the selected gates into FastAPI and emit versioned recognition events over HTTP/WebSocket; MQTT remains the device/event transport rather than the biometric decision engine.
