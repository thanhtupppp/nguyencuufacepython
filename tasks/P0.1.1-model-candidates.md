# P0.1.1 — Model candidate and license gate

## Status
ACTIVE — execution subtask of P0.1.

## Objective
Create a reproducible shortlist of detector/recognizer model artifacts that can be evaluated on real images without silently assuming that repository code licensing also covers pretrained weights.

## Current baseline
Primary architecture remains:
SCRFD -> 5-point alignment (112x112) -> ArcFace-compatible 512-D embedding -> quality gate -> person retrieval.

Do not change architecture until a benchmark shows a materially better accuracy/latency/licensing trade-off.

## Candidates
### A — InsightFace buffalo_l
- Detector: SCRFD det_10g
- Recognizer: ArcFace ResNet50, 512-D
- Status: RESEARCH / LICENSE BLOCKED for production until InsightFace licensing is explicitly verified.

### B — InsightFace antelopev2
- Detector: SCRFD det_10g
- Recognizer: ArcFace ResNet100, 512-D
- Status: RESEARCH / LICENSE BLOCKED for production until licensing is explicitly verified.
- Benchmark only if the artifact can be obtained lawfully for evaluation.

### C — Commercial-friendly alternative
- Candidate family: OpenCV Zoo YuNet + SFace or another explicitly commercial-permitted detector/recognizer.
- Status: ALTERNATIVE, not selected.
- Must be benchmarked against A/B with the same images, alignment, preprocessing, metrics and hardware before any architecture change.

## Required checks
1. Record exact artifact URL/source, release/version and SHA256.
2. Record model license/usage rights separately from source-code license.
3. Verify detector landmarks: 5 points and coordinate convention.
4. Verify recognizer input: 112x112, channel order, normalization and output dimension.
5. Verify L2-normalized embedding parity.
6. Run real-image smoke test with identical preprocessing.
7. Record PC CPU latency, peak memory and cold/warm inference latency.
8. Identify Raspberry Pi/Android deployment path using the same ONNX contract where possible.
9. Do not use synthetic vectors for identity-threshold calibration.

## Benchmark protocol
For every legally evaluable candidate:
- same image set;
- same detector confidence policy where applicable;
- same 5-point alignment contract;
- genuine pairs and impostor pairs;
- TAR/FAR at fixed FAR targets;
- FNMR/FMR or ROC/DET;
- p50/p95 embedding latency;
- peak RSS/memory;
- embedding dimension and model size.

## Completion criteria
- at least one legally evaluable candidate has a pinned artifact and reproducible inference;
- preprocessing/alignment contract is documented;
- baseline accuracy/latency measurements exist;
- production license status is explicit;
- any proposed architecture change has benchmark evidence.

## Next task
After this gate, build the real-image calibration/quality-gate dataset and determine acceptance/rejection thresholds using genuine/impostor distributions, then integrate the selected embedding contract into FastAPI E2E.
