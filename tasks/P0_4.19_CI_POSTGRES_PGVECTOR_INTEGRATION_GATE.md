# P0.4.19 — CI PostgreSQL/pgvector integration gate

## Objective
Run the existing PostgreSQL/pgvector person-level regression tests against a real pgvector service in GitHub Actions. Do not treat mocked, SQLite, or memory fallback execution as proof of database correctness.

## Verification
- CI starts `pgvector/pgvector:pg16`.
- Health check waits for PostgreSQL readiness.
- Unit tests run separately from integration tests.
- `tests/integration/test_pgvector_person_grouping.py` runs with real PostgreSQL/pgvector.
- The test verifies multiple embeddings for one person cannot hide the second person in top-k retrieval.

## Completion criteria
- Workflow completes successfully with a real pgvector service.
- Integration test passes without memory fallback.
- CI result is recorded as the execution receipt for P0.4.19.
- No recognition threshold or retrieval architecture decision is made from CI alone.
