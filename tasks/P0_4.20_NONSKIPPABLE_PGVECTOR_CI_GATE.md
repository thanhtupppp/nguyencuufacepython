# P0.4.20 — Non-skippable PostgreSQL/pgvector CI gate

## Objective
Turn the existing PostgreSQL/pgvector integration test into a real quality gate. A CI run must fail when PostgreSQL/pgvector is unavailable instead of silently skipping the test.

## Scope
- Register the `integration` pytest marker.
- Require `psycopg` for integration tests.
- Require a live PostgreSQL/pgvector connection when the integration suite runs.
- Preserve the person-level top-k regression: multiple templates for one person must not crowd out the second person before LIMIT.
- Keep unit tests and integration tests separately selectable in CI.

## Verification
1. Run `pytest -q -m "not integration"` in a clean environment.
2. Run `pytest -q -m integration` with `pgvector/pgvector:pg16`.
3. Confirm the integration test is not SKIPPED when the service is unavailable; it must FAIL.
4. Confirm the person-level grouping regression passes with 10 templates for person_A and 1 template for person_B.

## Acceptance criteria
- GitHub Actions executes both suites.
- Integration suite has zero skips caused by missing PostgreSQL/pgvector.
- The real pgvector service passes the person-level top-k regression.
- A missing/unreachable integration database produces a failing CI job.
- No recognition threshold or vector architecture is changed by this task.
