# P1.2.2 — FastAPI HTTP + WebSocket transport

Status: ACTIVE

## Objective
Expose the canonical RecognitionEvent through HTTP and WebSocket without allowing transport clients to bypass biometric validation.

## Implementation
- `app/main.py` provides `GET /healthz`, `POST /v1/events`, and `WS /v1/events/ws`.
- HTTP and WebSocket both validate the same Pydantic `RecognitionEvent` contract.
- Event IDs are idempotent within the process; a duplicate returns the original canonical payload.
- No inference, person matching, quality, or liveness decision is performed by the transport layer.

## Verification
Run `pytest`. Verify valid events are accepted, invalid confirmed events return 422, duplicate HTTP events are idempotent, and WebSocket serialization matches the canonical event representation.

## Completion criteria
- HTTP contract tests pass in CI.
- WebSocket contract tests pass in CI.
- Duplicate event behavior is deterministic.
- Transport layer cannot manufacture a confirmed `person_id` without passing the RecognitionEvent schema.
- Production persistence/idempotency is explicitly identified as a later database-backed task; the current in-memory store is test-only/minimal.
