# P0.4.7 — Transport-neutral action envelope and adapter contract

## Status
IMPLEMENTED — execution receipt pending.

## Objective
Freeze one authorization event schema shared by MQTT, HTTP and WebSocket so transport code cannot alter recognition semantics.

## Scope
- `ActionEnvelope` with schema version, event_id, camera_id, frame_index, track_id, person_id, authorization_state, timestamp.
- Only `AUTHORIZED` events may enter an action transport.
- `event_id` remains the idempotency key generated by the authorization coordinates.
- Transport adapters implement a common `send(envelope)` contract.

## Verification
1. Construct two equivalent authorized events and assert identical event IDs and payload fields.
2. Change frame/track/person and assert event ID changes.
3. Reject non-AUTHORIZED envelopes.
4. Replay the same envelope through transport adapters and verify the same event ID is preserved.
5. Add an execution receipt before binding a physical actuator.

## Completion criteria
- envelope and adapter contract implemented;
- focused tests pass;
- no transport-specific person_id or threshold logic exists;
- duplicate-delivery execution test exists before MQTT actuator integration.
