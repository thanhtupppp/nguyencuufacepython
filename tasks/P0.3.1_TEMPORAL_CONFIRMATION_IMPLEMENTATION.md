# P0.3.1 — Temporal identity confirmation implementation

Status: IMPLEMENTED — validation receipt pending CI/runtime replay.

## Objective
Prevent a single noisy recognition result from becoming a trusted `person_id` event while keeping `track_id` and `person_id` in separate namespaces.

## Implemented
- Deterministic state machine: `unknown -> candidate -> confirmed -> lost`.
- Same `person_id` must be observed for `min_consecutive` frames before confirmation.
- Rejected/unknown observations reset an unconfirmed candidate.
- A confirmed identity is never silently replaced by a conflicting candidate.
- Large frame gaps expire the track identity.
- Monotonic frame-index enforcement makes replay deterministic.

## Verification
Unit tests cover confirmation, conflicting candidates, unknown reset, confirmed identity protection, and expiry.

Production validation remains separate and must use labeled video replay to measure IDF1/HOTA (where available), identity switches, false person_id attachments, confirmation latency, recognition calls saved, and end-to-end latency.

## Safety contract
`track_id` is camera-local and never equals `person_id`. Cross-camera propagation requires an explicit identity event. `unknown` remains valid.
