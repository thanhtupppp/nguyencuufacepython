# P0.1 — SCRFD + ArcFace model gate

## Status
ACTIVE — next task after pgvector retrieval benchmark.

## Why now
The pgvector scale/filter benchmark completed successfully on 2026-09-08 (run #8). Prototype-per-person + exact template rerank is the leading retrieval candidate, but retrieval architecture is not fully locked because the 10k-person case at oversample 20 reached 98.1% recall@10 and the benchmark acceptance also requires broader `ef_search`/iterative-scan coverage and EXPLAIN ANALYZE BUFFERS.

## Goal
Select a legally usable, reproducible SCRFD detector + ArcFace-compatible recognizer for real-image evaluation without changing the recognition architecture prematurely.

## Required evaluation
1. Pin exact model artifacts, SHA256, input size, embedding dimension, preprocessing and normalization.
2. Verify model/weight license separately from repository code license.
3. Verify 5-point landmarks and 112x112 alignment compatibility with the repository alignment implementation.
4. Run real-image smoke test: detect -> landmarks -> alignment -> 512-D embedding -> L2 normalization.
5. Record CPU latency and memory on PC; keep an edge path for Raspberry Pi/Android.
6. Do not calibrate identity thresholds from synthetic vectors.
7. Produce a reproducible model manifest so PC/Raspberry Pi/Android deployments use the same model version.

## Primary architecture
SCRFD -> 5-point alignment (112x112) -> ArcFace 512-D embedding -> quality gate -> person retrieval.

## Model policy
InsightFace source code is MIT, but official pretrained recognition packs such as buffalo_l have separate licensing requirements. Do not commit or ship restricted weights until commercial/production rights are explicitly verified. If a commercial-friendly alternative is considered, benchmark it against the same real-image protocol before changing architecture.

## Completion criteria
- model artifact and license status recorded;
- real-image inference works reproducibly;
- embedding shape/preprocessing validated;
- alignment parity test passes;
- PC baseline latency recorded;
- edge deployment candidate identified;
- no unexplained model drift between devices.

## Next task
After this gate: build real ArcFace evaluation/calibration dataset and quality-gate thresholds, then benchmark false-match/false-non-match behavior before enabling production `person_id` recognition.
