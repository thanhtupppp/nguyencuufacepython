# P0.4.5 — FAS / identity authorization boundary

## Objective
Ensure a face action is authorized only when the tracked face is both temporally verified LIVE and independently confirmed as a person_id.

## Implementation
- `src/fas/authorization.py`
- `authorize_identity()` accepts FAS state, camera-local track_id, and already-confirmed person_id.
- FAS never creates or selects person_id.
- Any FAS state other than `LIVE_CONFIRMED` blocks.
- Missing identity confirmation blocks.

## Verification
- LIVE_CONFIRMED + confirmed person -> AUTHORIZED.
- SPOOF/ERROR/UNKNOWN/CANDIDATE_LIVE + confirmed person -> BLOCKED.
- LIVE_CONFIRMED + no person -> BLOCKED.
- No authorization decision may synthesize a person_id.

## Acceptance
- fail-closed;
- explicit track_id boundary;
- FAS and recognition responsibilities remain separated;
- deterministic unit tests pass in the project's test runner.
