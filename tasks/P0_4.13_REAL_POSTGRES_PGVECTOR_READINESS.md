# P0.4.13 — Real PostgreSQL/pgvector readiness

## Mục tiêu

Loại bỏ `VECTOR_DB_READY` như một readiness claim. `/readyz` chỉ được báo ready khi backend vector thực sự là PostgreSQL + pgvector và schema identity/vector tối thiểu tồn tại.

## Cách kiểm chứng

Probe phải kiểm tra theo thứ tự:

1. không dùng memory fallback;
2. không dùng SQLite fallback;
3. PostgreSQL connection tồn tại;
4. `SELECT 1` thành công;
5. extension `vector` tồn tại;
6. bảng `persons` và `face_embeddings` tồn tại.

## Tiêu chí hoàn thành

- memory/SQLite fallback luôn trả `503` qua `/readyz`;
- PostgreSQL thiếu pgvector trả `503`;
- thiếu bảng bắt buộc trả `503`;
- PostgreSQL + pgvector + schema đầy đủ mới có thể trả `200`;
- có deterministic unit tests cho từng failure mode và success path;
- không dùng synthetic DB state để tuyên bố production readiness.
