# P0.4.1 — Anti-spoofing model benchmark gate

## Objective

Select a passive presentation-attack detector without changing the recognition architecture prematurely. The first candidate family is MiniFASNet V1SE/V2 because it is small, ONNX-friendly and suitable for PC/Raspberry Pi/Android deployment. It is a candidate, not yet a production-approved model.

## Candidate evidence

- Silent-Face-Anti-Spoofing / MiniFASNet V1SE and V2: Apache-2.0 lineage.
- Current lightweight ONNX implementations report small model sizes and strong in-domain CelebA-Spoof results, but those figures are not accepted as project accuracy evidence until independently reproduced.
- Cross-domain FAS must be evaluated because printed-photo/screen replay performance does not establish robustness to unseen attack domains.

## Benchmark protocol

Evaluate at minimum:

1. bona-fide vs print;
2. bona-fide vs screen replay;
3. replay/video;
4. mask/partial presentation when available;
5. cross-camera/device;
6. low-light and non-frontal conditions.

Use subject-disjoint train/validation/test splits. Report APCER, BPCER and ACER where the dataset/protocol defines them, plus ROC-AUC and operating-point latency. Threshold is calibrated on validation only and frozen for the locked test.

## Integration contract

`SCRFD -> face crop -> anti-spoof -> if LIVE then alignment -> ArcFace`.

A spoof decision must prevent identity recognition and must never be hidden by lowering the ArcFace threshold.

## Acceptance

- exact model artifact, SHA-256 and license/provenance recorded;
- reproducible inference path on ONNX Runtime;
- validation-calibrated threshold;
- locked-test APCER/BPCER/ACER (where applicable);
- per-condition breakdown;
- PC baseline latency;
- edge-device feasibility assessment for Raspberry Pi/Android;
- no architecture replacement until a candidate beats the current gate on safety and deployment constraints.
