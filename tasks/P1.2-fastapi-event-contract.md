# P1.2 — FastAPI trusted recognition event contract

Status: ACTIVE

## Objective
Define the transport contract before model inference is integrated so PC, Raspberry Pi, Android, and ESP32 can use the same recognition event semantics without coupling biometric decisions to MQTT/HTTP/WebSocket transport.

## Core rule
`track_id` is not `person_id`. A `person_id` may only be emitted after quality, liveness, recognition threshold/margin, and temporal confirmation gates pass.

## Event states
- `DETECTED`
- `QUALITY_REJECTED`
- `LIVENESS_REJECTED`
- `RECOGNITION_CANDIDATE`
- `RECOGNITION_CONFIRMED`
- `UNKNOWN`
- `EXPIRED`

## Canonical confirmed event
```json
{
  "event_id": "uuid",
  "camera_id": "camera-01",
  "device_id": "edge-01",
  "track_id": "track-123",
  "person_id": "person-000123",
  "model_version": "arcface:<artifact-id>",
  "embedding_version": "v1",
  "quality": 0.0,
  "liveness": 0.0,
  "similarity": 0.0,
  "margin": 0.0,
  "frames_confirmed": 0,
  "timestamp": "RFC3339"
}
```

## Transport
- HTTP: synchronous inference/query and administrative APIs.
- WebSocket: low-latency camera/session events.
- MQTT: device/action events; ESP32 is a consumer/actuator, not a biometric decision maker.

## Security requirements
- Never send raw face images or embeddings over MQTT by default.
- Use TLS for HTTP/WebSocket/MQTT in deployed environments.
- `event_id` must be idempotent for downstream actions.
- Consumers must reject stale events using timestamp/TTL.
- `model_version` and `embedding_version` are mandatory for auditability.

## Verification
1. Schema validation tests for every state.
2. Confirmed event cannot be constructed without `person_id`, similarity, margin, quality and liveness fields.
3. Duplicate `event_id` is idempotent.
4. Stale event is rejected.
5. MQTT/HTTP/WebSocket adapters preserve the same canonical payload.

## Completion criteria
- JSON schema exists and validates.
- FastAPI endpoints are covered by contract tests.
- WebSocket and MQTT adapters serialize the same event.
- No transport layer can bypass biometric gates.
- End-to-end integration test uses deterministic mock recognition only; real model accuracy remains governed by P0.1/P0.2 benchmarks.
