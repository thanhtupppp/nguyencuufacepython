# P0.1.2 — Commercial-friendly face model benchmark

## Status
ACTIVE — next execution task after the InsightFace model-license gate.

## Why this task exists
Official InsightFace documentation currently states that the open-source code is MIT, while supplied pretrained models/training data are for non-commercial research and open-sourced recognition model packs such as `buffalo_l` require contacting InsightFace for licensing. Therefore the project must evaluate at least one explicitly redistributable/commercial-friendly baseline before production model selection.

## Candidate
OpenCV Zoo YuNet + SFace.
- Detector: YuNet (`face_detection_yunet_2023mar.onnx` family)
- Recognizer: SFace (`face_recognition_sface_2021dec.onnx` family)
- Candidate use: legally cleaner production baseline; NOT an architecture replacement yet.
- Record the exact upstream artifact URL, release/version, SHA256 and model license before downloading or committing any weights.

## Goal
Determine whether a cleanly licensed detector/recognizer can meet the project's accuracy, false-match, latency and edge-deployment requirements. Do not compare headline model scores; compare end-to-end behavior under the same images, enrollment protocol, alignment policy and thresholds.

## Protocol
1. Freeze an evaluation image manifest outside git; use consented/internal images or a permitted public face-recognition benchmark.
2. Run the same enrollment/query protocol for every candidate.
3. Record detector recall/failure cases separately from recognition errors.
4. Apply the project's 5-point 112x112 alignment contract where the candidate exposes compatible landmarks; otherwise document the adapter and its effect.
5. Measure genuine/impostor cosine distributions.
6. Report TAR at fixed FAR targets (1e-2, 1e-3, 1e-4 where sample count supports it), ROC/DET, FNMR/FMR, and top-1 identification accuracy.
7. Measure p50/p95/p99 warm and cold CPU latency, peak RSS, model size and ONNX Runtime compatibility.
8. Test PC first, then Raspberry Pi/Android feasibility using the same model artifacts and preprocessing.
9. Do not tune thresholds to hide retrieval/index misses; model evaluation and vector retrieval evaluation remain separate gates.

## Architecture rule
The primary architecture remains SCRFD -> 5-point alignment -> ArcFace-compatible embedding -> quality gate -> person retrieval until a benchmark proves a replacement is materially better on accuracy/safety/latency and licensing.

## Completion criteria
- Exact artifacts and SHA256 pinned.
- Weight/model license explicitly documented.
- Reproducible real-image inference works.
- Genuine/impostor benchmark results recorded.
- PC latency/memory recorded.
- Edge feasibility recorded.
- Decision is one of: (a) retain InsightFace pending commercial license, (b) adopt OpenCV candidate, or (c) reject OpenCV candidate with measured reason.

## Next task after completion
Build the real-image quality-gate calibration dataset and threshold/margin calibration around the selected embedding contract.
